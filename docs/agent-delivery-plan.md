# Agent 分阶段交付计划

更新日期：2026-11-09

本文把 Agent 的后续工作拆成可以独立开发、独立验收和独立回滚的功能包。每个功能包都必须从
`develop-agent`（或已经明确声明的前置功能分支）创建 `feature/*` 分支，专项测试和相关全量
回归通过后才能合入开发总分支。未完成真实环境验收的能力不标记为完成。

## 1. 不影响现有功能的约束

1. 普通聊天仍然是默认路径：输入问题后直接得到回答，不默认加载面试报告、Skill、RAG 或业务工具。
2. 新字段优先使用可空字段或版本化 JSON，旧接口、旧数据和旧动作状态机保持可读。
3. 新工具默认只读；写操作必须继续使用现有草稿、确认、幂等和审计链路。
4. 诊断信息只进入 Trace、运行详情和可展开区域，不把 Loop、Token、内部状态堆到主聊天输出。
5. 任何恢复逻辑都不能根据不完整的 Provider 信息自动重放未知副作用；不确定时停止并提示核对。
6. 每项功能都要覆盖正常、失败、超时、重试、刷新、重启、并发、权限和副作用边界。

## 2. 功能包和依赖关系

| 包 | 内容 | 分支建议 | 依赖 | 兼容策略 | 验收门槛 |
| --- | --- | --- | --- | --- | --- |
| A0 | 真实 Provider 多轮验收 | `feature/agent-real-provider-eval` | 当前 Agent 运行时 | 只增加采集和门禁，不改业务行为 | 普通问答、Skill/RAG、报告、工具、补充、确认、取消、断线和并发 |
| A1 | 记忆来源链 | `feature/agent-memory-provenance` | P0 记忆治理 | 记忆 JSON 新增可选元数据，旧数据字段为空仍可读 | 来源字段、脱敏、旧 JSON、编辑/撤回、Prompt 不泄漏 |
| A2 | 内部模型轮次与恢复检查点 | `feature/agent-durable-turn-checkpoint` | A0、现有 RunState | 先只读记录；精确续跑由开关控制，默认安全重生成 | Provider 轮次、工具批次、等待状态、重启和不重复副作用 |
| A1.5 | 会话输入草稿隔离 | `feature/agent-draft-persistence` | 现有会话切换 | 仅浏览器当前标签页缓存，不写服务端、不进模型上下文 | 切换、刷新、发送清理、通用/面试会话隔离、存储异常回退 |
| A3 | 全领域工具结果契约 | `feature/agent-domain-result-contracts` | A2 | 只在工具边界校验和包装，不改变领域 API | 简历、记忆、训练、文件和日程的结果码/资源 ID/状态 |
| A4 | 证据冲突和事实支持度 | `feature/agent-evidence-verifier` | A0、A2 | 先记录评估状态，不阻断回答；后续按评测结果决定是否提示 | 引用缺失、来源冲突、无命中、事实支持度分层 |
| A5 | 精确预算和缓存指标 | `feature/agent-token-budget-metrics` | A0、A2 | 字符预算继续作为安全兜底，Provider 不支持时保持现状 | 实际 Token、估算 Token、裁剪原因、缓存命中和费用 |
| B1 | MCP Gateway | `feature/agent-mcp-gateway` | A3、A4、正式认证 | 外部 Server 白名单、Scope、owner 映射、限流和审计；默认关闭 | 外部工具只读试运行、越权和提示注入拒绝 |
| B2 | 外部日历/会议连接 | `feature/agent-external-calendar` | B1 | 先查询和草稿，发送邀请、取消和改期仍需确认 | OAuth、权限、幂等、冲突、撤销授权和真实回调 |
| B3 | 有界子 Agent | `feature/agent-bounded-subagent` | A2-A5 | 独立预算、权限、超时和结果 Schema；不引入自由协作网络 | 只有复杂任务收益明确时才立项 |

依赖顺序：

```text
A0 真实验收
  ↓
A1 记忆来源链 ─────────────┐
  ↓                         │
A2 轮次检查点 → A3 工具契约 → A4 证据评估 → A5 预算指标
                                             ↓
                              B1 MCP → B2 外部日历
                                             ↓
                              B3 有界子 Agent（按需）
```

A1 可以与 A0 并行，因为它只扩展记忆数据结构；A2 以前不直接改变恢复语义。B1 以前不把任意
外部 MCP 工具放入 Agent 工具目录。

## 3. 每个功能包的交付流程

1. 开发前：写明目标、非目标、旧路径、数据兼容和回滚方式。
2. 开发中：只修改本功能包涉及的模块；跨模块改动必须增加契约测试。
3. 专项验收：单元测试、服务测试、权限测试、失败/超时/重试、重启和并发场景。
4. 相关回归：Agent 全量后端测试、评估任务、前端 TypeScript/Vite 构建。
5. 真实验收：涉及 Provider、数据库、队列、Redis 或外部服务时，必须在候选环境执行真实脚本。
6. 合入前：检查 `git diff --check`、迁移脚本、未跟踪文件和分支差异；只合入 `develop-agent`，
   不自动推送、不修改 `master`、不直接部署正式环境。

## 4. 当前执行项

当前分支：按功能包分别验收；最近已完成 `feature/agent-memory-provenance`、
`feature/agent-run-checkpoint-version`，当前推进 `feature/agent-draft-persistence`。

本分支正在实现 A1.5：

- Agent 输入草稿按会话写入当前标签页 `sessionStorage`；
- 切换会话或刷新页面后恢复对应草稿，通用会话与面试会话互不串稿；
- 发送成功开始运行时清理草稿，不写入服务端历史，也不进入模型上下文；
- 存储不可用时回退到原有内存草稿逻辑；
- 通过专项测试后，再执行前端构建和相关 Agent 回归，最后才具备合入条件。

当前已完成的可靠性增量还包括：

- RunState 增加 `checkpoint_version`；旧记录按 v1 兼容，未知版本延迟自动恢复；
- Agent 输入草稿按会话写入当前标签页 `sessionStorage`，发送成功后清理，切换会话不串稿。
- 生产工具白名单优先从 `AgentToolRegistry` 的能力描述生成，静态工具集合仅作为无注册中心
  的迁移/测试兜底；普通对话仍不挂载业务工具，现有工具回调的安全校验和确认链路不变。

真实 Provider 验收、内部轮次精确恢复、MCP 和外部会议连接仍然是后续独立功能包，不能因为
离线测试通过就提前宣称完成。

真实交互验收矩阵当前包含 9 个场景，覆盖普通多轮、显式面试上下文、Skill/RAG 组合、提示注入
拒绝、日程缺信息续跑、创建确认、创建后取消草稿以及创建后取消已存在日程。采集脚本会回收
自己创建的线程、面试和已确认日程；如果外部环境回收失败，会输出需要人工核对的资源 ID。

2026-11-09 在候选环境 `18084` 执行首个普通双轮场景时，真实模型回答状态为 `COMPLETED`，但
远程响应的用量摘要缺少 `estimatedPromptTokens`，因此被观测门禁拒绝，不能记为真实验收通过。
这表明该环境尚未部署包含当前 Agent 预算观测契约的版本；重新验收前必须先更新部署并确认
接口返回实际/估算输入 Token、模型轮次事件和工具轨迹字段。
